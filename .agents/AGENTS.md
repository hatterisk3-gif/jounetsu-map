# AI Assistant Rules

- **Cleanup Temporary Files**: Always delete any temporary scripts, scratch files, or AI-generated artifacts (such as `update_*.js`, `.py` scripts, or `.txt` tracking files) immediately after the task or feature implementation is successfully completed. Do not leave temporary files in the workspace.
- **Production Backend is Supabase + Cloudflare R2 (Not GAS)**:
  - Production traffic runs on **Supabase (PostgreSQL + Auth + RLS + Edge Functions) + Cloudflare R2** by default (`supabase-config.js` sets `enabled: true`).
  - Frontend `callGAS()` calls are intercepted by `api-client.js` (`PassionMapApiRouter`) and handled by `supabase-bridge.js` (REST API) and Edge Functions under `supabase/functions/` (`auth-gateway`, `r2-presign`, `market-sync`, `gemini-proxy`).
  - For normal feature additions, bug fixes, or data read/write changes, **modify `supabase-bridge.js` (and/or `supabase/functions/*`, `supabase/migrations/*`) — do NOT modify `コード.js`**, because changes to `コード.js` do not affect production except for the remaining GAS-fallback actions (Google Calendar integration, external spreadsheet cultivation-plan import/export, shared catalog bulk chunk writes, Google Maps short-URL expansion) or emergency `?backend=gas` rollback.
  - Never expose or commit secrets (`migration/.env`, `migration/data/`, `supabase/.temp/`, `sb_secret_*`, `SUPABASE_SERVICE_ROLE_KEY`, `R2_SECRET_ACCESS_KEY`, `GEMINI_API_KEY`, `MARKET_SYNC_SECRET`) in frontend code or git.
- **Update Release Notes & Cache Busters on Deploy**: Whenever committing and deploying changes (via `/deploy` or user instruction), always prepend a new entry to `window.PASSION_MAP_RELEASES` in `release-notes.js` with `id` incremented by `+1`, `date` (`YYYY-MM-DD`), `tags` (array of feature category labels such as `'畝CAD・図面'`, `'栽培計画'`, `'マップ・圃場'`, `'作業画面'`, `'スケジュール'`, `'出退勤・休憩'`, `'農薬・資材'`, `'市況・原価'`, `'機械・車両'`, `'看板・ピン'`, `'天気・環境'`, `'お知らせ・システム'`), and `message` (the commit message without `Manual: `), and update `release-notes.js?v=...` in `worker.html`, `worker2.html`, and `admin.html` (plus `cacheBust` in `schedule.html`) before running `git add .` and `git commit`. Whenever `supabase-bridge.js` or `supabase-config.js` is modified, also bump its `?v=...` query string to the new `id` across the 17 static HTML files (while `schedule.html` uses `cacheBust`).
